## Bug desk `/fix`

The screen answers: **What exactly will leave this browser when I export the intake?** Its biggest element is the editable failure beside its local review, rather than a description of unavailable features.

Taste Skill 2.1.4 app workflow: `framed-sheet`, seed `250956056`, retaining palette and type. The paper ground frames one quiet sheet. The product has two useful destinations, so its existing top navigation replaces an unnecessary sidebar. Archivo carries the interface; Plex has one technical role for source, filenames and SHA-256. The signature element is the paired original-input and review sheet, with exact-byte identities and a compact execution gate. There are no entrance animations; motion is limited to press feedback with reduced-motion support.

- Inputs remain only in React page memory. No storage persistence, upload, API call or native form submission is attached to this screen.
- Review validates input shape and size, never Python behavior. Errors focus a linked summary; review actions reopen and focus the original field. Any edit retires the reviewed packet and its identities.
- Clear retains one undo copy only in page memory until another edit, clear or navigation. Undo requires a fresh review.
- Downloads retain the existing `mend_bug_intake`, schema 1 JSON and filename. Exact source text and line endings survive. The JSON identity hashes the actual serialized UTF-8 download including its final newline. The separate raw-source identity is not the backend's whole-file identity.
- Hashing is local and optional for export. Pending work cannot attach an old fingerprint to edited inputs; a failed hash is shown as unavailable. No backend identity, signature or execution evidence is inferred from a fingerprint.
- Optional protected-test inputs stay in the same page memory. A separate explicit review requires original module source, expected behavior, proposed `test_regression.py`, unique required unittest IDs and one target from that list. Combined source is limited to 200,000 UTF-8 bytes. The optional disclosure follows the main intake action so error-only intake remains compact.
- `mend-bug-review-request.json` contains only the backend preparation input fields: `intake`, `protected_test_source`, `required_check_ids`, `target_check_id`. Review shows the proposed source, named checks and exact JSON; it labels proposals unapproved and not executed. No browser-side contract/hash implementation or backend request is added. Existing fingerprints identify the nested intake only; request export never claims a contract identity.
- Every proposed-field edit, clear or undo also invalidates the review and pending intake fingerprints. Existing intake export remains schema 1 and excludes proposed checks; the separate review request is consumed by the offline CLI `--request` option. Neither export approves or executes the recipe.

Browser evidence and the selected sheet live under `.taste-skill/bug-desk/`; terminal browser artifacts live under `output/playwright/`. They are local QA artifacts, not application assets or execution receipts.
