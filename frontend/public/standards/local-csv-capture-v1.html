MEND / BUILD TYPE SPECIFICATION

Local CSV capture, version 1

This build type describes the curated CSV-cleaner source and its local Python check capture. It does not describe inference, an autonomous repair, a Nebius job, or a SLSA security level. An unsigned statement is not an identity attestation.

Standard envelope

_type: https://in-toto.io/Statement/v1
predicateType: https://slsa.dev/provenance/v1

Inputs and execution

The builder reads the committed example/csv_tools.py, example/test_csv_tools.py, and scripts/capture-example.py. It verifies those input bytes against the source commit. The capture script removes the exact empty-input guard for the before run, executes the same checks in separate temporary directories, then executes the unchanged checked-in source for the after run. The resulting stderr, stdout, exit codes and timestamps are recorded without replacing them with an illustration.

python3 scripts/capture-example.py --output dist/example/captured-run.json
python3 scripts/provenance.py prepare --repo-root . --capture dist/example/captured-run.json --artifact dist/example/csv_tools.py --output dist/example/provenance.json

The source URI may be supplied with --source-uri for a checkout whose native provider does not persist an origin remote. It must identify the actual repository, not an invented public GitHub location.

Parameter interpretation

entryPoint names the capture script. parameters records the capture/check inputs and reproduction arguments. trigger records the actual local or workflow invocation. resolvedDependencies binds repository URI and Git commit; source, test and capture-script hashes bind the observed bytes. runDetails.builder.id identifies the actual local or GitHub builder, never an unobserved Nebius job. Metadata preserves the recorded execution interval. The subject SHA-256 identifies the produced artifact bytes.

Signing and verification

Keyless signing uses a genuine OIDC identity and cosign. The bundle must retain its Fulcio certificate and public transparency-log inclusion evidence. Verification pins the expected certificate identity and OIDC issuer, checks the subject artifact digest, and requires the attested statement to match. No self-reported browser status flag is a verification result. Failed or unavailable signing leaves the document unsigned.

Signing this local capture does not upgrade it into evidence of Nebius execution, autonomous diagnosis, production readiness or merge approval.
