# Reproduce the available offline demo

This command connects the existing capture, repository-review CLI, simulated backend receipt export and JavaScript receipt inspector. It needs **Python 3.12, Node.js 24** and the installed backend package. It accepts no user code, credentials or URLs. It never starts a provider client or changes a hosted database. Only the known repository CSV example is actually executed. The repository proposal is inert text; service execution is simulated.

From a fresh repository root, create and activate a private Python virtual environment as described in [the judge guide](JUDGE_GUIDE.md), then install and run:

```sh
python -m pip install './backend[test]'
python backend/scripts/verify_offline_demo.py --output-dir ../mend-offline-demo
```

Choose a **new** output directory outside the checkout. The command refuses existing directories without replacing their files. It retains partial new outputs on failure and only writes `summary.json` after every check passes. Exit status 0 means these five offline checks passed; 1 means failure; 2 means Node.js is missing. The initial package installation may access the package registry; the smoke command itself performs no network operation. Run it only on source you have reviewed: local execution is not a sandbox.

The output contains:

| File | What it demonstrates |
| --- | --- |
| `captured-example.json` | Actual curated Python original failure and known correction, with source/check identities. The correction is not generated by a model. |
| `repository-request.json`, `repository-case.json` | Frozen explicit multi-file request and proposed protected oracle; neither executes the repository nor approves the oracle. |
| `repository-candidate.json`, `repository-review.json` | Two editable files changed and a source-bound diff produced. Execution/apply/approval remain disabled. |
| `repository-tampered.json` | Deliberately changed protected test rejected by the CLI; `must-not-exist.json` must not be created. |
| `ide-fixture/receipt.json`, `ide-fixture/workspace/` | Actual `TaskService` receipt and verified bundle from `FixtureModel`/`FixtureRunner` and `LocalTestStore`; simulated execution, `local_test`, unsigned. |
| `ide-fixture/inspection.txt` | JavaScript viewer independently matches exact exported source and protected checks while displaying the unsigned label. |
| `summary.json` | All five checks completed, with their limits. It is not a live execution receipt or signed proof. |

To inspect interactively, install the [receipt viewer VSIX](IDE_RECEIPTS.md#install-a-local-vsix), open `ide-fixture/workspace` in VS Code and run **Mend: Inspect Local Receipt**, choosing `ide-fixture/receipt.json`. Edits to saved workspace files should produce a mismatch when inspected again. This does not verify a signature, actual protected execution or stop timing. Do not confuse this fixture with a real provider-backed run.

The regression invokes the full command and then attempts the same output directory again, checking every existing file hash is preserved. The repository-review stage also checks protected-file tampering fails without emitting a review. CI executes this regression in the backend suite. Public frontend and live/cloud acceptance remain separate gates in [release readiness](RELEASE_READINESS_2026_10_24.md).
