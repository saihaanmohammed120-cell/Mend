# Review inside Mend

The owner requested both in-app navigation and working screens for local repository, policy and receipt tools. The implementation stays in the existing frontend. Both live-provider and hosted-database holds remain active; no backend, auth, budget, execution or hosted schema change is included.

- `/tools#repository`: select bounded Python files or provide exact JSON source maps. Compare the same path set, inspect original/candidate SHA-256 identities and conservative changed spans, and flag changed protected files. Test modules and the tests package are always locked. Comparison is not Python parsing, dependency resolution, a backend frozen contract or executed regression evidence.
- `/tools#policy`: preview chosen changed-line/byte thresholds against that comparison. Protected changes and excess limits require review. Approval stays unavailable without trusted history, authenticated regression and operator signing authority. A within-threshold result is not a server policy approval.
- `/tools#receipt`: inspect a supported unsigned SLSA v1 statement or backend schema-1 CSV receipt. Actual browser hashing follows the existing IDE source-map identity format. SLSA subjects bind only named selected source bytes. A missing file stays unavailable; a known mismatch stays a mismatch. Live/fixture JSON labels, check assertions and job identities are unauthenticated. No signature or stop-proof verification is claimed.
- `/help`: readable steps, technical references for all six roadmap topics, selected implementation files and MIT notices. It is built from an explicit public-source inventory, without request-controlled filesystem paths. There is no runtime content fetch or external-page dependency. Homepage source/testing/license links and all roadmap guides use this internal reader. Bug intake/workspace link back to tools/guides. The sample footer points to in-app evidence limits.
- Existing provenance now also has a full JSON disclosure in the page, alongside explicit optional downloads and its existing honest hash checker.

Inputs remain in browser page memory; tool switching retains them, while explicit Clear/reload/leaving clears them. No form submission, source upload, persistence, provider client, private key or execution authority is added. Pending local reads/hashes are fenced by a revision so edited/cleared inputs cannot acquire stale results. JSON/source/receipt size bounds, duplicate-key checks, Unicode and path checks apply before a result is accepted. Source text preserves UTF-8 content, BOM and CRLF for content identity.

The browser implementation of whole-snapshot identity is cross-checked with the existing IDE implementation, including Unicode/BOM/CRLF. Receipt contract JSON is compared as parsed data with the existing IDE reference in unit tests. The conservative span matches the existing backend policy metric; this is not a second implementation of trusted policy approval. No new dependency or automatic animation is added.

Changed source: the new local-review library/reference, tools component, shared desk shell/styles, tools/help routes, and focused unit/browser tests; existing landing, roadmap, provenance, intake, workbench and sample navigation; design and judge guides; this report and the publication fingerprint manifest. Generated screenshots/logs remain local QA artifacts, not receipts or published product assets.

Verification uses the project's own frontend unit, type, lint, build and production browser commands. Exact observed output, release SHA, CI and direct public acceptance are recorded separately in the local verification report and the exact-commit Actions run. Previous release counts are not evidence for this change.

Remaining: hosted authentication/backend/migrations, live provider repair, trusted policy authority/history, independent stop evidence, signing, team-hosted workflows and required branch administration. The local browser tools neither activate nor certify them. The old ChatGPT Site is separate and is not updated by this Vercel release.
